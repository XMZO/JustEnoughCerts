# 数据与备份

[English](backup.md)

## 数据目录

JEC 的全部数据存放在数据目录中（容器中为 `/data`，即 `docker-compose.yml` 同级的 `./data`）：

| 文件 | 内容 |
|---|---|
| `jec.db` | SQLite 数据库：证书、私钥、服务商与凭据（敏感内容已加密）、签发与部署记录、设置；数据保存在 [PostgreSQL](postgresql.zh-CN.md) 时没有此文件 |
| `secret.key` | 主密钥，用于解密数据库中的敏感内容；通过 `JEC_SECRET_KEY` 传入主密钥时不生成此文件 |
| `config.yaml` | 可选的服务器运行配置，参见[配置参考](configuration.zh-CN.md) |
| `plugins/` | 可选的插件程序，参见[插件](../development/plugins.zh-CN.md) |
| `hooks/` | “运行脚本”通知渠道使用的脚本 |

> [!WARNING]
> 缺少主密钥将无法解密已保存的私钥与凭据。主密钥须与数据库一同备份，或另行妥善保管。

## 备份

以下方式任选其一：

- 备份整个数据目录（含 `secret.key`）。
- 在设置页的“数据和备份”中选择“下载备份”，输入登录密码后下载数据库的一致性副本。JEC 在下载期间照常运行。下载的备份不含主密钥。

如需将配置纳入 Git 管理或迁移至另一实例，可使用 YAML 配置文件，参见[配置导入导出](config-file.zh-CN.md)。

## 每日自动备份

在设置页的“数据和备份”中选择保留的份数：关闭（默认）、3、7、14 或 30 份。开启后 JEC 每天在数据目录的 `backups/` 中生成一份备份，以生成时间（UTC）命名，如 `jec-20261020-020000.db`，并删除超出份数的最早备份。这些备份与下载的备份相同：不含主密钥，恢复方法也相同。关闭后，已生成的备份保留不动。请另行将备份复制到其他机器：数据目录中的备份无法应对磁盘损坏。

## 升级前的备份

新版本的 JEC 启动时，如需迁移 SQLite 数据库，会先将数据库复制到 `backups/`，以时间（UTC）命名为 `upgrade-<时间>.db`，并只保留最近三份。需要退回原版本时，停止 JEC，将该文件复制到数据目录并命名为 `restore.db`，再启动原版本：JEC 以该备份替换数据库，并将较新的数据库保留在旁边。使用 PostgreSQL 时，请在升级前用 `pg_dump` 自行备份。

## 异地备份

“异地备份”模块将每份每日自动备份复制到 S3 兼容的对象存储（如 AWS S3、Cloudflare R2、MinIO，以及阿里云 OSS、腾讯云 COS 的 S3 接口），或 WebDAV 文件夹（如坚果云、Nextcloud、群晖、Alist）。须先开启每日自动备份。

1. 创建存储桶，以及可写入该存储桶的访问密钥。
2. 在设置页的“数据和备份”中，点击“异地备份”旁的“设置存放位置”，选择“S3 兼容存储”，填写：

   | 字段 | 内容 |
   |---|---|
   | 接口地址 | S3 接口的地址，如 `https://s3.us-east-1.amazonaws.com`、`https://<账户>.r2.cloudflarestorage.com` |
   | 存储桶 | 存储桶名称 |
   | 区域 | 留空为 `us-east-1`；Cloudflare R2 填 `auto` |
   | 路径前缀 | 可选，如 `jec/` |
   | 路径形式的地址 | 存储桶写在地址的路径中，MinIO 和自建服务通常需要 |
   | Access Key、Secret Key | 第 1 步的访问密钥 |

3. 保存。JEC 先写入并删除一个小文件 `jec-write-test.txt`，无法写入时不保存设置。

使用 WebDAV 时选择“WebDAV”，填写存放备份的文件夹地址（如坚果云 `https://dav.jianguoyun.com/dav/jec/`、Nextcloud `https://<主机>/remote.php/dav/files/<用户名>/jec/`）、可选的子文件夹、用户名和密码（坚果云须使用“第三方应用密码”）；不存在的子文件夹由 JEC 创建。

JEC 每 15 分钟查找新的备份，每份以原文件名复制一次；设置页的这一行显示已复制的份数、时间和最近的错误。JEC 不删除存储桶或文件夹中的任何文件，旧备份请用存储桶的生命周期规则清理，或自行删除。复制的备份与备份本身相同，不含主密钥，主密钥须另行保管。

本模块只对 SeaweedFS 的 S3 接口和 rclone 的 WebDAV 服务实测过。

## 恢复

**在界面中恢复**：在设置页选择“恢复”，上传备份文件并输入登录密码。JEC 首先检查备份：文件完整、属于 JEC、使用当前主密钥加密，且数据库版本不高于当前程序。检查通过后 JEC 停止运行，由 Docker 或 systemd 服务重新启动并载入备份；原数据库连同其 WAL 文件重命名为 `jec.db.before-restore-<时间>` 保留在数据目录中。其他运行方式须自行重新启动 JEC。

**手动恢复**：停止 JEC，将备份文件放入数据目录并重命名为 `jec.db`，然后启动 JEC。
