# 用真实账号试 JEC

[English](trying.md)

阿里云 ESA、ESA 边缘应答和 Namecheap SSL Manager 都还只对着替身测过（见 [providers.zh-CN.md](providers.zh-CN.md)）。这份清单按“域名在 ESA 建站、DNS 在腾讯云 DNSPod、证书在 Namecheap 买”的场景，一步步用真实账号试一遍，并写明每一步该看到什么、出问题时要记下什么。只想用免费证书的，做到第 4 步就够了。

试的时候请用测试版或 main 分支：把 `deploy/docker-compose.yml` 里镜像的 `latest` 换成 `beta`。所有密钥都在 JEC 的界面里填，不要写进文件、截图或聊天记录。

## 1. 准备密钥

- **阿里云**：在 RAM 访问控制里建一个子账号，创建 AccessKey，授予 ESA 部署要的 `esa:ListSites`、`esa:ListCertificates`、`esa:SetCertificate`、`esa:DeleteCertificate`；要用边缘应答，再加 `esa:*Kv*` 和 `esa:*Routine*`（`PLAN.md` 5.4 列了每一项）。
- **腾讯云**：在访问管理（CAM）里建一个子用户，授予 `QcloudDNSPodFullAccess`，创建 API 密钥。

在 JEC 的“凭据”页分别添加“阿里云 AccessKey”和“腾讯云 API 密钥”。也可以先跳过，在下面添加服务商时选“新建凭据”，填的密钥会自动存成凭据。

## 2. 部署目标：阿里云 ESA

“部署目标”页 →“添加部署目标”→“阿里云 ESA 站点”：凭据选阿里云的，接入点选中国站（`esa.cn-hangzhou.aliyuncs.com`），站点填 ESA 里的站点名。保存后点“测试连接”。

- 应该看到“连接正常：站点 … 现在有 N 张证书”。
- 报权限不足或站点不存在时，记下界面上的提示和日志里的错误码。

## 3. 域名验证：DNSPod

“域名验证”页 →“添加验证方式”→ 搜索“Tencent Cloud DNS”：凭据选腾讯云的。保存后点“测试连接”，应该看到“连接正常：这个账号能管理 N 个域名……”，里面有你的域名。

## 4. 先用免费证书走一遍

1. “证书来源”页添加“ACME 账号”，证书颁发机构选 Let's Encrypt。
2. “证书”页添加证书：域名填 ESA 站点上的域名，来源选刚才的 ACME 账号，验证方式选 DNSPod，部署目标选 ESA。
3. 签发进度页会一步步显示日志：下单、添加 TXT 记录、等 CA 验证、取回证书。签好后自动部署到 ESA。
4. 到 ESA 控制台的证书列表看：应该多了一张名字以 `jec-` 开头的证书；再签一次（证书详情里的“立即签发”）后，上一张应该被删掉，免费版的 2 个位置不会被占满。
5. 几分钟后看证书详情里的“线上检查”：应该是新证书。

出问题时，把签发进度页或部署记录页的日志整段复制下来（日志里没有密钥），连同 ESA 控制台里看到的情况一起记下。

## 5. ESA 边缘应答（可选）

“域名验证”页添加“ESA 边缘应答”，凭据选阿里云的，“用来测试的域名”填 ESA 站点上的一个域名，点“测试连接”。第一次会自动建边缘 KV 命名空间 `jec_validation`、边缘函数 `jec-validation` 和站点上 `/.well-known/` 的路由，可能要等一两分钟；测试超时就过一会儿再测。

成功后，可以再添加一张证书，验证方式选 ESA 边缘应答（ACME 会走 HTTP-01）。请记下：边缘函数和路由在 ESA 控制台里是否出现、测试花了多久、有没有报错。

## 6. Namecheap SSL Manager

1. “模块”页打开 Namecheap 模块（标着“实验”）。
2. 在 Namecheap 面板里激活或重签那张 PositiveSSL，选 Server-side automation，复制给出的一次性令牌（24 小时内有效，只能用一次）。
3. “证书来源”页添加“Namecheap SSL Manager”，填一次性令牌，保存后马上点“测试连接”：这一步用令牌注册。
4. 添加证书：域名填那张证书的域名（只支持单域名），来源选 Namecheap，验证方式选 ESA 边缘应答（或者网站目录、JEC 自己应答）；Namecheap 如果给的是 DNS 验证，就选 DNSPod。
5. 签发会进入“等待来源”，每 5 分钟看一次 Namecheap 的状态，可能要等几个小时到一天。

这一步有几件事只有真实账号才知道（`PLAN.md` 5.6 的“还不确定”），请留意日志里的这些信息：

- 测试连接后，JEC 能看到账户里的哪些证书：只有选了 Server-side automation 的那一张，还是全部。
- 交了验证之后、签出之前，日志里“Namecheap 上的状态”显示的是什么。
- Namecheap 给的是 HTTP 文件验证还是 DNS 验证；DNS 验证的话，记录名是完整的域名还是相对的名字。
- 是否出现“CSR 不是这次签发交的”“还没有证书”之类的等待提示。
- 第二张证书（200 天后的那张）要不要重新拿令牌注册。

## 7. 记下什么、发给谁

- 每一步成功还是失败，界面上的提示文字。
- 失败那一步的完整日志（从签发进度页或部署记录页复制）。
- Namecheap 的状态名、ESA 控制台里看到的变化。

不要发：AccessKey、API 密钥、一次性令牌、数据目录里的 `secret.key` 和数据库文件。
