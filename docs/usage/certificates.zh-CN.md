# 证书

[English](certificates.md)

“证书”页列出全部证书及其状态、剩余有效期、来源、部署目标与下次续期时间；在手机上，需要处理的证书单独列出并注明原因。各状态的含义见[核心概念](../guide/concepts.zh-CN.md#证书状态)。

## 添加证书

在“证书”页选择“添加证书”。添加方式取决于证书来源：

| 方式 | 说明 |
|---|---|
| 由证书来源签发 | 选择证书来源，填写域名，选择验证方式与密钥类型。提交后立即开始签发，此后自动续期 |
| 手动上传 | 来源选择“手动上传”，粘贴 PEM 文本（证书、中间证书与私钥，顺序不限），或上传 PFX/P12 文件及其密码。此类证书不会自动续期，到期前发出提醒 |
| 导入已有证书 | 选择“导入已有证书”，与手动上传相同，适用于迁移已有的证书 |
| 生成 CSR | 向商业 CA 手动购买证书时使用，参见下文 |
| 批量添加 | 选择证书来源后，在域名上方选择“多张证书”，每行填写一张证书，同一行的多个域名用空格或逗号分隔；表单其余设置对每张都适用。无法添加的行连同原因保留，可修改后再次提交 |

域名的处理规则：

- 第一个域名为主域名；通配符写作 `*.example.com`。
- 域名统一转换为小写，国际化域名转换为 Punycode，重复的域名自动去除。
- 通配符证书须使用 DNS 验证；只填 `*.example.com` 时，页面提示加上 `example.com` 本身。
- 也可以填 IP 地址（如 `192.0.2.1`、`2001:db8::1`），只能用网站目录类的验证方式；Let's Encrypt 只给 `shortlived` 配置签发 IP 证书（参见[证书来源](sources.zh-CN.md)）。
- 添加页默认选中上次添加证书时用的证书来源、DNS 服务商与部署目标（记在当前浏览器中）。证书列表菜单与证书信息中的“以此为模板添加”则从那张证书的来源、验证方式、部署目标、续期天数与密钥类型开始。
- 选用腾讯云 DNSPod、阿里云 DNS、Cloudflare 或华为云 DNS 时，页面会核对每个域名是否在该账号里，不在时提示，避免签发时才失败。该预检只用替身测过，结果仅供参考。
- 选用 DNS 服务器名称已知的服务商（如 Cloudflare、DNSPod、阿里云、Route 53、GoDaddy、Namecheap）时，页面会查询每个域名所在区域的 DNS 服务器（`_acme-challenge` 有 CNAME 时按其目标），不属于该服务商时提示。
- 选用已持有证书的来源（本机证书目录中 certbot、acme.sh 的证书，或从阿里云、腾讯云取回的证书）时，页面列出尚未以该来源添加的证书：点击即填入其域名；在“多张证书”中点“全部加入”则每张一行。
- 同一张证书（按指纹）只能添加一次。

密钥类型可选 RSA 2048/3072/4096 与 ECDSA P-256/P-384，默认值在设置页的“续期默认值”中设置。每次续期都会生成新的私钥。

只上传了证书本身、没有中间证书时（例如从证书颁发机构的邮件里复制的），JEC 按证书中的颁发者地址（AIA）下载中间证书补齐证书链，避免部署后部分客户端（如 Android、curl）不信任。

证书列表的“下载全部证书”把每张证书的当前版本连同私钥打包成一个 ZIP（每张一个文件夹），用于离线留存或迁移到别处；下载前须输入登录密码，审计日志逐张记录。

从其他工具迁移时，在“手动上传”中选择“多个文件”，一次选择导出的全部证书和私钥文件（PEM、CRT、CER、KEY 等，可分开也可混在一起）：JEC 按公钥把私钥与证书配对、补齐证书链，逐张加入；已有的证书保持不变，找不到私钥的证书和读不出的文件分别列出。

证书详情页“证书信息”中的备注可记录证书的用途或归属；证书列表会显示、搜索并导出备注。

同一处的“提醒”可设定一个日期和事项（例如“续费 PositiveSSL 订阅”）：到当天 9:00（面板时区）经通知渠道提醒一次（通知事件“证书上设置的提醒到期时通知”），日历订阅中也会出现；配置文件中为 `reminder`（`day`、`note`）。适用于购买的证书：订阅到期后无法再重签，需提前续费。

在宽屏的证书列表中勾选多张证书（表头的复选框选择当前显示的全部），可一起立即续期、重新部署或删除（执行前会先确认），也可一起暂停或恢复自动续期，一起添加、移除某个部署目标（例如更换 CDN 时），或一起更换验证方式（例如 DNS 换服务商时）。

证书列表的搜索框按域名、备注查找；输入主机名（或粘贴网址）时，也会找到覆盖它的通配符证书，例如搜索 `api.shop.com` 会找到 `*.shop.com`。

### 向商业 CA 购买的证书

在证书商处购买、需要提交 CSR 才能签发的证书（例如手动激活的 PositiveSSL），可以由 JEC 生成私钥和 CSR，私钥加密保存在 JEC 中，不经过别处：

1. 添加证书时来源选择“生成 CSR”，填写域名并选择密钥类型（商业证书一般都接受 RSA 2048）。提交后页面显示 CSR，可复制或下载为 `.csr` 文件。
2. 在证书商处激活或重签证书时提交这份 CSR，按其要求完成域名验证。
3. 证书签发后，在证书详情页选择“上传证书”，只粘贴证书（可含中间证书），私钥留空：JEC 自动配上生成 CSR 时的私钥。在添加证书页直接上传也会自动归到对应的证书。

等待签发期间证书显示为“等待证书”，并列入“需要处理”。续费重签时，在证书详情页选择“生成 CSR”得到新的私钥和 CSR；证书商用同一份 CSR 重签时，上传的证书会配上当前版本的私钥。

## 证书详情

证书详情页包含：

- 剩余有效期、签发与到期时间、有效期长度与下次续期时间；
- 部署目标及每个目标最近一次部署的结果；
- 上次续期（或最近一次签发）的步骤与用时；
- 线上检查的结果，参见[续期](renewal.zh-CN.md#线上巡检)；
- 历史版本与证书链；
- 证书信息（域名、颁发者、来源、密钥、序列号与 SHA-256 指纹）与续期设置。

## 操作

| 操作 | 说明 |
|---|---|
| 立即签发 / 立即续期 | 立即开始一次签发，不等待续期时间 |
| 修改域名 | 证书信息中“域名”旁的铅笔：改动有证书来源的证书的域名，保存后立即按新域名签发；签发进行中时不能修改。上传的证书以证书文件为准 |
| 上传新证书 | 为证书添加新版本。新证书须包含原主域名，且到期时间晚于当前版本 |
| 选择部署目标 | 增删部署目标。新增的目标立即部署当前版本 |
| 立即部署 / 重新部署 | 将当前版本重新部署到全部或单个目标 |
| 下载 | 下载 ZIP 文件，内含 `cert.pem`、`chain.pem`、`fullchain.pem` 与 `privkey.pem`；可选同时生成供 Windows、IIS、Azure 与 Java 导入的 `certificate.pfx`（可设密码，可选兼容旧系统的 3DES 加密）。文件含私钥，下载前须输入登录密码 |
| 更换验证方式、密钥类型 | 在“续期设置”中修改，从下一次签发起生效，例如域名的 DNS 换了服务商时 |
| 更换证书来源 | 在“续期设置”中修改，从下一次签发起生效，已有的版本保持不变。上传的证书改用来源后开始自动续期；由 certbot 续期的证书可改由 ACME 账号签发。签发进行中时不能更换；配置文件不更改来源 |
| 部署时段 | 在“续期设置”中选择新版本部署到目标的时段（如 01:00 至 05:00，按面板时区），避开白天重载服务；线上巡检从部署时起计算。手动部署立即进行；配置文件中为 `deploy_window` |
| 暂停自动续期 | 在“续期设置”中勾选后，证书不再自动签发，只在选择“立即签发”时签发；到期提醒照常发送。适用于迁移 DNS 或准备下线的域名；配置文件中为 `paused` |
| 改用较早版本 | 在“历史版本”中把未过期、未吊销且域名相同的较早版本重新设为当前版本，并部署到全部目标；用于新版本出现问题（如部分客户端不认它的证书链）时回退。之后的续期按该版本的到期时间计算 |
| 吊销 | 在“历史版本”中吊销较早的版本，须选择原因并输入登录密码，详见下文 |
| 拉取地址 | 证书信息中的“拉取地址”：JEC 连不到的服务器（内网或 NAT 后的机器）可以定时用 curl 拉取当前版本的证书与私钥，见下文 |
| 删除证书 | 删除证书的全部版本与私钥。已部署到其他位置的证书不受影响 |

证书列表的每一行也提供上述常用操作的菜单。

## 由服务器拉取证书

JEC 无法连接的服务器可以自己定时拉取证书：

1. 在证书详情的“证书信息”中，点击“拉取地址”旁的“设置”，输入登录密码，生成密钥。密钥只显示这一次。
2. 在服务器上定时运行页面给出的命令（如 cron 每小时一次）：

   ```sh
   curl -fsS -H "Authorization: Bearer jecpull_..." --etag-compare fullchain.pem.etag --etag-save fullchain.pem.etag \
     -o fullchain.pem https://jec.example.com/api/v1/certs/pull/fullchain.pem
   ```

   证书未变化时服务器返回 304，文件保持不变。可拉取 `fullchain.pem`、`privkey.pem`、`cert.pem` 与 `chain.pem`；拉取后请自行重载使用证书的程序。

密钥放在请求头中而不是地址中，不会出现在访问日志里。生成新密钥后旧密钥立即失效，也可随时关闭拉取。每次拉取都记入审计日志。

## 吊销证书

由 ACME 账号或支持吊销的插件来源签发、尚未过期且不是当前使用中的版本可以吊销。吊销后证书颁发机构将其列入吊销列表，检查吊销状态的客户端不再信任该证书；此操作无法撤销。要吊销当前使用的版本（例如私钥泄露时），请先选择“立即签发”，新版本部署完成后再吊销旧版本，这样网站不会使用已吊销的证书。

| 原因 | 适用情形 |
|---|---|
| 已有新证书取代它 | 吊销较早版本时的常见原因 |
| 私钥已泄露 | 私钥已暴露；JEC 为每个新版本生成新的私钥 |
| 其域名已不再使用 | 已放弃这些域名 |
| 不说明原因 | 以上都不适用 |

网站不再使用时，可在删除对话框中勾选“同时在 CA 吊销”并输入密码：所有仍有效的版本以“其域名已不再使用”吊销（当前使用的版本最后吊销），然后删除证书。CA 拒绝吊销任何一个版本时，不删除证书，当前使用的版本也保持有效。

其他来源的证书（如手动上传或厂商服务的证书）请在获取证书的地方吊销。
