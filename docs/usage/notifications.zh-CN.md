# 通知

[English](notifications.md)

通知渠道在“通知”页管理。证书发生选定的事件时，JEC 按每个渠道所选的语言生成消息并发送。卡片上的“发送测试”用于立即发送一条测试消息。

## 事件

| 事件 | 默认 |
|---|---|
| 签发失败 | 开启 |
| 部署失败 | 开启 |
| 证书快到期或已经过期 | 开启 |
| 网站上还是旧证书（线上巡检发现） | 开启 |
| 网站发送的证书链缺少中间证书（同上） | 开启 |
| 证书被 CA 吊销（参见[吊销检查](renewal.zh-CN.md#吊销检查)） | 开启 |
| 监控的站点证书快到期或已经过期（参见[到期监控](sites.zh-CN.md)） | 开启 |
| 域名注册快到期或已经过期（同上） | 开启 |
| 证书透明度日志里出现不是 JEC 管理的证书（同上，须先开启） | 开启 |
| 有新证书（签发或上传） | 关闭 |
| 部署成功 | 关闭 |
| 部署目标、DNS 服务商或证书来源未通过每日自检（每个支持测试连接的服务商每天测试一次，与卡片上的“测试连接”相同；设置改动前只通知一次。未通过的服务商也显示在总览的“需要处理”中） | 开启 |
| 有人连续登录失败、被暂时锁定（参见[账号与安全](../operations/security.zh-CN.md)） | 开启 |
| 有人登录面板（同上） | 关闭 |
| JEC 有新版本（须在设置页开启“自动检查更新”，参见[升级](../guide/installation.zh-CN.md#升级)） | 开启 |
| 每周概况（每周一 9:00 后，按面板时区）：需要处理的证书、未来 7 天的续期，以及测试失败的服务商、需要留意的站点与域名、证书透明度中待查看的证书 | 关闭 |

单张证书的通知可以只发给部分渠道：在证书详情的“续期设置”中勾选“通知发给”的渠道（例如某个团队的证书只发到他们的群），都不勾选时发给全部渠道；配置文件中为 `notify_to`。

每周概况也可用来确认 JEC 仍在运行：某一周没有收到时值得检查。每个渠道可单独选择事件与消息语言。消息标题以“【JEC】”开头，便于在群聊中识别；设置了 `JEC_BASE_URL` 时，消息附带对应页面的链接。同一事件不会重复发送到同一渠道；超过 3 天仍未送达的消息不再发送。

每个渠道还可设置免打扰时段（22:00 至次日 07:00、23:00 至次日 08:00 或 00:00 至 08:00，按面板时区）：这段时间里的消息先保存，时段结束后再发送；发送失败时每 10 分钟重试，最多 6 次。通知页的渠道卡片显示待发送的时间。测试消息不受免打扰影响。

## 通知渠道

| 渠道 | 说明 |
|---|---|
| 电子邮件 | 经 SMTP 发送，同时带纯文本与 HTML 两种格式（链接可点击） |
| Telegram | 机器人令牌与会话 ID；可设置代理与自建 API 地址 |
| 钉钉、飞书（Lark）、企业微信 | 群机器人；关键词可设为 `JEC`；钉钉与飞书支持加签 |
| Server酱 | 按 SendKey 区分 Turbo 版与 Server酱³ |
| Bark | 默认使用官方服务器，也可使用自建服务器 |
| ntfy、Gotify | 可使用自建服务器 |
| Discord | 频道的 Webhook 地址 |
| Slack | Incoming Webhook，兼容 Mattermost 与 Rocket.Chat |
| Pushover | 用户密钥与应用令牌 |
| Microsoft Teams | Workflows 的 Webhook 地址，以卡片发送 |
| Google Chat | 聊天室的 Webhook 地址 |
| Matrix | 服务器、访问令牌与房间（ID 或别名）；可使用自建服务器 |
| PushPlus（推送加） | 用户令牌；可推送到群组，或改用企业微信、邮件 |
| QQ（OneBot v11） | 经自行运行的 NapCat、Lagrange 等的 HTTP 接口，发到群或个人 |
| Webhook | 以 JSON 或自定义模板发送；可设置签名密钥、请求头、请求方法与 Content-Type |
| 运行脚本 | 由内置 shell 运行数据目录 `hooks/` 中的脚本，参见下文 |

可自建服务端的渠道（Bark、ntfy、Gotify、Matrix、QQ、Slack、Webhook）提供“允许内网地址”开关，默认只连接公网地址。连接境外服务的渠道（Telegram、Discord、Slack、Teams、Google Chat、Matrix、Pushover、ntfy、Gotify、Bark、Webhook）可在高级设置中单独设置代理。

## Telegram 机器人的指令与菜单

Telegram 机器人除发送通知外，还可在其聊天中回应指令：

1. 在通知渠道中编辑该机器人，打开“接收指令和菜单”。如需在 Telegram 中操作，再打开“允许在 Telegram 里操作”。
2. 在该聊天中发送 `/menu`，机器人回复菜单。点击按钮时，菜单在同一条消息中原地更新。

| 指令 | 内容 |
|---|---|
| `/menu` | 主菜单：证书数量与状态、下次续期时间，以及各项入口 |
| `/certs` | 全部证书及剩余天数，点击进入单张证书 |
| `/todo` | 需要处理的证书及原因，以及测试失败的服务商 |
| `/recent` | 最近 7 天的签发、续期与部署 |
| `/online` | 线上检查发现的问题 |
| `/sites` | [监控的站点与域名注册](sites.zh-CN.md)，需要留意的排在前面；以及证书透明度中需要查看的证书 |
| `/help` | 指令说明 |

单张证书的页面显示状态、剩余天数、续期时间、来源、颁发者、部署情况、线上检查与最近一次签发。允许操作时，页面另有“立即续期”“重新部署”“立即检查”与“暂停/恢复自动续期”按钮；续期与重新部署需再次确认。

- 机器人只回应设置中“发给谁（Chat ID）”指定的聊天；其他聊天发送 `/start` 时，机器人仅回复该聊天的 ID，便于填写。
- 机器人以面板账号的身份读取和操作，不能修改账号；审计日志中显示为“经 <机器人名称>”。
- 同一个机器人令牌只能在一处接收指令。机器人设置了 Webhook 时，无法接收指令。
- JEC 只回应开始接收之后发送的指令，停机期间发送的指令不会补做。
- 接收指令时，这个机器人发出的通知下方带一个按钮：关于证书的通知打开该证书的页面，站点与域名的提醒打开“到期监控”，每周概况打开主菜单。按钮的内容以新消息发出，通知本身保持不变。

## 运行脚本

“运行脚本”渠道用于对接其他系统：

- 脚本放在数据目录的 `hooks/` 中（首次使用时创建，仅属主可访问），由内置 shell（兼容 POSIX sh 与 Bash）运行，最长 20 秒。
- 消息以环境变量 `JEC_EVENT`、`JEC_TIME`、`JEC_TITLE`、`JEC_SUBJECT`、`JEC_TEXT`、`JEC_LINK` 提供；事件关于某张证书时另有 `JEC_CERTIFICATE_ID`、`JEC_DOMAIN`、`JEC_DOMAINS`、`JEC_NOT_AFTER`、`JEC_FINGERPRINT`。标准输入为整条消息的 JSON，格式与 Webhook 相同。
- 退出码 0 表示成功；75 表示暂时失败，稍后重试；其他退出码、语法错误与超时不再重试。

## 日历订阅

通知页底部的“日历订阅”可在 Apple、Google、Microsoft 等日历应用中显示证书的到期时间（提前 7 天提醒）与下一次续期的开始时间；到期监控模块开启时，还包括监控的站点证书与域名注册的到期时间。

1. 开启日历订阅，JEC 显示订阅地址。
2. 在设备上选择“添加到日历”，或复制地址后在日历应用中按网址添加订阅。事件文字使用复制地址时的界面语言；将地址末尾改为 `lang=en-US` 或 `lang=zh-CN` 可更换语言。

由于日历应用无法登录，订阅地址中含有私密的密钥：知道该地址的人都能看到域名与日期。选择“换新地址”会生成新的密钥，旧地址随即失效；关闭日历订阅后地址同样失效。该功能由“日历订阅”模块提供，可在“模块”页停用。
